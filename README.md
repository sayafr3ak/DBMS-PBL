# PCETS — Police Complaint & Evidence Tracking System

DBMS Project 59 · **MySQL 8** (3NF schema, constraints, triggers, views, procedures) + **Python / Flask** web application.

## Quick start

```bash
pip install -r requirements.txt
python setup_db.py          # creates police_evidence_db + sample data (reads config.ini)
python run.py               # http://127.0.0.1:5000
```

Copy `config.example.ini` to `config.ini` and set your MySQL password. MySQL credentials are in `config.ini` (or env vars `PCETS_DB_HOST/PORT/USER/PASSWORD/NAME`).

There is **no login page** — the app opens directly as `admin` (`default_user` in `config.ini`).
Use the **Acting as** selector at the bottom of the sidebar to switch role:

## Live deployment (Clever Cloud)

Live app: **https://app-f830abc4-c524-45b9-bef6-9a9c73e64e95.cleverapps.io/** — Python app `pcets` (nano, Paris) linked to the MySQL add-on `policedb`.

Clever Cloud's DEV MySQL refuses `CREATE TRIGGER` / `CREATE FUNCTION` (binary logging, no SUPER privilege) and allows
only 5 connections. The app therefore runs in **hosted mode** there: when no triggers exist it issues the CMP/EVD numbers,
writes the status history and checks the trigger rules itself (keys, CHECK and foreign keys are still enforced by MySQL).
On a local MySQL the real triggers are installed and the Integrity Lab shows MySQL rejecting every rule.

App environment variables: `CC_PYTHON_MODULE=run:app`, `CC_PYTHON_BACKEND=gunicorn`, `CC_PYTHON_VERSION=3`,
`PCETS_DB_POOL_SIZE=0` (one connection per request), `TZ=Asia/Kolkata`, `PCETS_SECRET_KEY`; `MYSQL_ADDON_*` come from the linked add-on.

```bash
npm install -g clever-tools && clever login
python setup_db.py                       # build the local DB (source of the sample data)
# with MYSQL_ADDON_HOST/PORT/USER/PASSWORD/DB set to the add-on's credentials:
python tools/deploy_db.py                # schema + procedures + views + data into the add-on
clever deploy                            # push the committed code (git) and restart
```

## Business rules → enforcement

| Rule | Mechanism |
|---|---|
| Unique complaint / evidence IDs | UNIQUE keys + numbers generated by triggers (`CMP-YYYY-NNNNN`, `EVD-YYYY-NNNNN`) |
| Complete custody transfer | NOT NULL + `chk_custody_from` + trigger `trg_custody_bi` (handing officer = current holder, no gap) |
| Valid case status | CHECK + workflow trigger `trg_complaint_bu` (preconditions: officer, charge, court ref) |
| No overlapping custody | UNIQUE on generated `open_key` + interval-overlap check + append-only log |
| Closure details required | CHECK `chk_complaint_closure` (CLOSED ⇔ date, type, remarks, officer) |

Open **Integrity lab** in the app to run all 26 violation scenarios live (each is rolled back).
